## Findings

### Aggregate views

**Architecture delta** — deliberate and consistent: the AD-5 shared `{ok, data, reason}` event envelope, established in Story 2.2, was faithfully reused by 2.3 and 2.4 with no drift; each new Rust module (`weather.rs`, `stream_info.rs`) mirrors `directory.rs`'s existing "pure parse split from the network call" shape. No layering violations or unplanned cross-cutting dependencies.

**God-class growth — confirmed, and the exact risk flagged as a watch item in Epic 1's retro one hour ago was not acted on.** `winradio/src-tauri/src/audio/player.rs` grew from 650 lines at the end of Epic 1 to **1015 lines** at the end of Epic 2 (`git show 98d63bf:...player.rs | wc -l`) — +365 lines added, zero deleted, confirmed via `git_evidence.py`'s per-file churn for this range. All of that growth is three near-identical "dedup check → optional async fetch spawned off the critical path → generation-guard → emit ok/err" blocks, one added per story (Location in 2.2, Weather in 2.3, Stream Info in 2.4), with no extraction into a shared abstraction despite each story visibly copying the previous one's shape.

**Duplication map — confirmed, literal, not just "similar":**
- `should_emit_location_update`, `should_emit_weather_update`, `should_emit_stream_info_update` (`player.rs:722`, `:734`, `:747`) are byte-for-byte identical 5-line functions — same body, different name only. Verified by direct diff of the three function bodies. The signature (`&mut Option<String>, &str -> bool`) doesn't touch `self` at all — nothing prevented calling one shared function three times with three different `Mutex` guards. Each copy carries its own 3-test suite, so 9 tests currently cover one 5-line logic three times over.
- Weather's (`player.rs`, Story 2.3) and Stream Info's (`player.rs`, Story 2.4) `tokio::spawn`-based fetch-and-emit blocks in `run_playback` are structurally near-identical — the only real difference is which async call is awaited (`weather::fetch_weather` vs. `stream_info::resolve_ip`). A natural candidate for one generic helper that was not extracted.

**Pattern divergence** — none of note beyond the duplication above. Each story otherwise faithfully followed the established envelope/dedup/generation-guard conventions — which is what makes the non-extraction a clearer process gap than "divergent conventions": the pattern was recognized and consistently copied, just never generalized.

**Spec-to-implementation reconciliation — a genuine win worth recording, not just a defect:** Story 2.4 explicitly set out to avoid repeating Story 2.2's shipped dropped-fields bug (`toggleFavorite` silently dropping new station fields) by adding `codec`/`bitrate` correctly the first time — confirmed in `spec-2-4-stream-info-tile.md`'s own Boundaries & Constraints ("get it right the first time, don't repeat that story's dropped-fields bug") and its Code Map. Evidence that a lesson learned *within* a session/epic does transfer — in contrast to `deferred-work.md` items, which do not (see Process findings).

### Cross-story boundary finding: the reconnect-blanking bug (found and fixed this session)

A stream drop/reconnect to the *same* station left the Location, Weather, and Stream Info tiles permanently blank for the rest of that station's playback — the clearest example this epic produced of a defect no single story's own review could see. Root cause: `player.rs`'s retry loop re-emits `"play"` on every reconnect (not just a genuine switch); the frontend (`playback.ts`) unconditionally reset every tile to idle on `play`; and each tile's own dedup guard — introduced independently by Stories 2.2, 2.3, and 2.4, each copying the previous story's shape — correctly suppresses re-emitting that tile's own event on a same-station reconnect (by design, to avoid a needless refetch). Each story's own review verified its tile's dedup logic in isolation and missed the interaction with the shared `play`-triggered reset. It surfaced only when two independently-run review lenses (edge-case-hunter and verification-gap), both reviewing Story 2.4's diff, independently converged on the same bug. Fixed in commit `f65046d` with regression tests covering both the same-station (state preserved) and different-station (state reset) cases, verified via `npx vitest run` (55/55 passing) before merge.
