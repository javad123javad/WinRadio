## Findings

### Aggregate views

**Architecture delta** — Story 1.1's "foundation rescue" is the epic's one major structural change: deleted `lib.rs` entirely, removed EQ/recording (`cpal`/`lame-sys`/`hound`), removed a dangling Vue Router import, swapped in `stream-download`+`icy-metadata`+`rodio` for the audio pipeline, and fixed a real `#[serde(rename_all = "camelCase")]` wire-format bug. Well-documented, well-reviewed (8 patch findings caught and fixed in its own review round), no further major architectural changes for the rest of the epic. — Source: `spec-1-1-...md`'s Spec Change Log and Suggested Review Order.

**God-class watch** — `winradio/src-tauri/src/audio/player.rs` was the epic's highest-churn file (561 added / 390 deleted in Story 1.1 alone) and stood at 650 lines by the end of Epic 1 (confirmed via `git show 4f68214:winradio/src-tauri/src/audio/player.rs | wc -l`). Not a violation within Epic 1 alone — it's a legitimate concentration of the connection/retry state machine plus the audio decode pipeline — but it was already the single largest, most concern-dense file in the codebase at epic's end, before Epic 2 added three more emit blocks to the same file. Worth a watch note, not a fix-now.

**Duplication / structural risk — Station-shape field parity (confirmed real, already caused a shipped bug):** the fields shared between `DirectoryStation` (`winradio/src/stores/search.ts:10`), the frontend `Station` interface (`winradio/src/stores/stations.ts:6`), the Rust `Station` struct (`winradio/src-tauri/src/commands.rs`), `toPlayableStation` (`search.ts:44`), and `toggleFavorite`'s add-branch (`stations.ts:138`) are kept in sync by hand across 4-5 separate places with no structural safeguard — no single conversion function, no test asserting every `DirectoryStation` field has a `Station` counterpart. This is not hypothetical: Story 2.2's own review caught `toggleFavorite` silently dropping `country`/`geoLat`/`geoLong` (a shipped bug, patched), and Story 2.4 had to add the same category of field (`codec`/`bitrate`) carefully by hand to avoid repeating it. The pattern will recur for the next field added to either shape.

**Spec-to-implementation reconciliation:**
- Story 1.1: one legitimate scope correction during planning — "last-played station shows idle with last volume restored" was mis-drafted into Story 1.1's frozen intent, correctly flagged by the implementer as unbuilt, and moved to Story 1.5 where it belonged. Process working as intended, not a defect.
- Story 1.8's "the Sleep Timer default set here pre-fills Story 1.7's duration picker" is implemented as a visual highlight only (`text-primary` class on the matching preset in `TransportBar.vue:93`) — the user still must click one of the 4 presets; nothing auto-arms on open. Verified via direct read of `TransportBar.vue:78-108`. No loopback was recorded against this reading in Story 1.8's Spec Change Log, so it was accepted as the intended interpretation at the time — recorded here as a verified-consistent reading, not a new finding.
- **`lastStation` snapshot divergence (confirmed real, zero test coverage):** `settings.ts`'s `lastStation` (set by Story 1.5) is a frozen full `Station` snapshot taken at play-time. If that same station is later favorited, renamed, reordered, or unfavorited (Story 1.4's live editing), `restoreLastStation` (`playback.ts`) never reconciles by id against the current Favorites list on relaunch — it displays the stale snapshot verbatim. Confirmed still true by reading current `playback.ts`/`settings.ts`. Checked `playback.test.ts` and `settings.test.ts` for coverage: every `lastStation` test asserts a verbatim persist/restore round-trip; none exercises the divergence scenario (a station changing after being set as `lastStation`) — a regression here would ship with a fully green suite.

### Cross-story boundary review

Performed as a targeted, evidence-based inspection of the Favorites↔Search shape boundary (1.2/1.4), the last-played-station↔live-Favorites boundary (1.4/1.5), and the Settings↔Sleep-Timer wiring (1.7/1.8) — narrower than a full dual-lens `bmad-review` pass over the whole diff, given each story already carries its own completed 3-layer review and the highest-value cross-story risks were identifiable directly from the code. The two real findings from this pass are the field-parity risk and the `lastStation` divergence above; the Sleep-Timer/Settings boundary checked out as intentional.

### Process-level findings (epic-scale, not story-scale)

These emerge only from reading all 51 of Epic 1's `deferred-work.md` entries together — each one was individually reasonable to defer at the time, but the clusters below were invisible to any single story's own review:

1. **Accessibility debt compounds silently.** At least 9 of the 51 entries are accessibility gaps — missing ARIA roles/labels, no focus trap/restoration in the Settings modal, color-only state indicators, a `<label>`-vs-`<div>+<span>` inconsistency within `SettingsModal.vue` itself (items in Stories 1.1, 1.4, 1.7, 1.8). Each was correctly caught by that story's own review and individually deferred; none has been fixed as of this retro, and EXPERIENCE.md's "accessibility floor" was never revisited as its own follow-up.
2. **"No component-level test tooling" was flagged 5 separate times** (Stories 1.2, 1.4, 1.5, 1.7, 1.8), each as its own recorded item. Confirmed still true today: `winradio/package.json` has no `@vue/test-utils` or DOM test environment. A single investment would have closed 5 recorded gaps at once; recording each occurrence separately hid that they were one gap.
3. **Persistence robustness is one recurring root cause, not 5 separate issues.** No rollback on save failure, no coalescing of overlapping saves, no atomic file write (`Store::save()` uses plain `std::fs::write`, no temp-file+rename), and the `lastStation` staleness above — first flagged in Story 1.1, repeated with each new persisted field since (Stories 1.4, 1.5). Never centralized into one fix.
4. **`deferred-work.md` has no triage or lifecycle.** 51 entries from Epic 1 alone (plus ~20 more from Epic 2, per this session's earlier work), append-only, no status field, no severity, no owner — nothing has ever been marked fixed even incidentally. It functions as a write-only backlog; the clusters above were only visible because this retrospective read all of it end-to-end.
5. **Verification never included an actual installed release, across either epic, until today.** Every story's own "Verification" section runs `cargo build`/`cargo test`/`npm run build`/`tauri dev` — never `tauri build` followed by installing and launching the real bundled artifact. This exact gap is how the `Cargo.toml` `custom-protocol` packaging bug (present since the project's initial scaffold — its `custom-protocol = []` feature never forwarded to `tauri/custom-protocol`) shipped undetected through all of Epic 1 and Epic 2, only caught today when the user actually installed and ran the v0.2.0 release. Already fixed this session (commit `cb25712`); recorded here so the process gap that let it happen doesn't silently recur.
